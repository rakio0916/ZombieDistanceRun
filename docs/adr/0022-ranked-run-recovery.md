# ADR-0022: 残ったランキング走行を明示的に破棄して再挑戦する

- 日付: 2026-09-22
- 状態: `VERIFIED`（設計とローカル実装を検証。実機と認証付き一連の操作は未検証）
- 文脈: 認証済み開始が200で`RUNNING`を発行した後、ページ再読み込みでclientのrun ID・入力が消えると、serverは31分間409を返す。通常ブラウザーでの再開始失敗を本番ログとD1で確認した。

## 判断

409で所有者のactive run IDを返し、利用者の明示操作から所有者限定の`abandon`を呼んで、記録なしの`REJECTED`へ移した後に再開始する。通信結果が不明な場合も勝手に走行を破棄せず、次の開始の409から回復する。開始失敗で練習へ自動移行しない。

## 理由と影響

自動破棄は別タブで進行中の走行を奪う。本人が破棄対象の説明を読んで操作する方式なら、その走行を続ける選択を残せる。所有者照合と`RUNNING`条件付き更新で、他人の走行と確定済みの順位を保護する。D1 schema・競技Core・旧run再生は維持する。[34章](../34_RANKED_START_RECOVERY.md)に実装と検証範囲を記録する。
